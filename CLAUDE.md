# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

笔记 (Notes) — A desktop note-taking application built with **React 19 + TypeScript + Vite + Electron 41**. Uses **Zustand 5 + immer** for state management and persists data via an Electron IPC bridge (`window.notesApi`). Supports knowledge bases → document trees → Markdown editing, plus search, tags, favorites, trash, version history, share links, and presentation mode.

## Commands

```bash
npm run dev          # Start dev server (Vite + Electron concurrently)
npm run dev:web      # Vite only (no Electron)
npm run typecheck    # tsc --noEmit
npm run build        # tsc -b + Vite production build (output to dist/)
npm run lint         # ESLint
npm run test:unit    # Vitest unit tests
npm run test:e2e     # Playwright E2E (requires dev server on :5173)
npm run start        # Run built Electron app
pnpm verify          # Gate: typecheck + lint + unit tests + build (CI runs the same command)
pnpm verify:all      # Gate + E2E (playwright webServer builds and serves automatically)
npm run icons        # Regenerate app icons (scripts/build-icons.cjs → build/icon.ico|png)
npm run dist:dir     # electron-builder unpacked build → release/win-unpacked (fast validation)
npm run dist         # electron-builder NSIS installer + portable → release/
```

Packaging config lives in the `build` field of `package.json` (electron-builder, output `release/`). Icons are generated by `scripts/build-icons.cjs` (pure Node PNG/ICO encoders — no image dependencies); replace `build/icon.*` with a real design asset when available. Both the `dist` script and `build.electronDownload.mirror` point at npmmirror for China networks; drop them for GitHub reachable networks.

Packaging rules that are easy to break:

- **`dependencies` must contain only `jszip`.** Every renderer dependency is bundled by Vite into `dist/`; anything left in `dependencies` gets copied into `app.asar` verbatim (asar 7.3 MB → 152 MB, installer 95 MB → 124 MB). The main process only `require`s `electron`, node builtins and `jszip` — verify with a grep before moving a package back.
- **`build.electronDist` points at `node_modules/electron/dist`** so packaging reuses the locally installed Electron instead of re-downloading ~120 MB; keep it in sync with the `electron` devDependency version.
- **`patches/app-builder-lib@26.15.3.patch`** (wired through `patchedDependencies` in `pnpm-workspace.yaml`) fixes an upstream bug: electron-builder 26.15.3 uses `ElectronDownloadCacheMode` from `@electron/get`, which `@electron/get@3` does not export, so every download path (Electron runtime, NSIS/winCodeSign toolset) throws `TypeError: Cannot read properties of undefined`. Re-check before removing the patch on an electron-builder upgrade.
- **`electron-winstaller` build scripts stay denied** (`allowBuilds` in `pnpm-workspace.yaml`): only electron-builder's Squirrel target needs it, and unresolved build approvals make `pnpm install` exit non-zero, which breaks `pnpm dist` via pnpm's pre-run dependency check.

## Architecture

### Entry & Shell
- `src/main.tsx` — App entry: lazy-loads `App.tsx` inside `ErrorBoundary` + `Suspense`
- `src/App.tsx` — Root component (~330 lines). Owns layout, panels wiring, keyboard shortcuts, auto-save/draft hooks; no per-view routing (see below)
- `src/components/app/MainContent.tsx` — Picks the active view (Start / QuickNote / Tags / Trash / Favorite / Recent / Notebooks)

### State Management (`src/store/`)
- Single Zustand store (`useNotesStore`) built from **slices** in `src/store/slices/`:
  - `coreSlice.ts` — notebooks/docs CRUD, trash, active ids, persistence (load/save)
  - `versionSlice.ts` — version restore helpers (`getDocVersions` / `restoreVersion`)
  - `shareSlice.ts` / `commentSlice.ts` / `tagSlice.ts` / `searchSlice.ts` / `undoRedoSlice.ts`
- **Auto version snapshots** are written inside `coreSlice.updateDoc` (30s merge window, max 50 versions) — `versionSlice.saveVersion` was removed as dead code; do NOT re-add a second writer
- Persistence via `window.notesApi.load()` / `.save()` (IPC `notes:load` / `notes:save`) — defined in `electron/main.cjs` + `electron/preload.cjs`
- ID generation: `newId()` in `src/store/storeUtils.ts`

### Type Definitions (`src/types/`)
- Core types: `NoteDoc`, `Notebook`, `Tag`, `TrashDoc`, `ShareLink`, `DocVersion`, `SearchResult`, etc.
- `AppStore` is defined in `src/types/notebook.ts`; `src/types/electron.d.ts` re-imports it and declares the global `window.notesApi`

### Component Structure (`src/components/`)
Panels are lazy-loaded in `MainContent.tsx` / `App.tsx` via `React.lazy` + `<LazyLoader>`:

### Utilities (`src/utils/`)
- `editorTextOps.ts` — Textarea manipulation helpers (wrap/insert/indent/align/clear formatting), extracted from `Editor.tsx`
- `autoSaveUtils.ts` — Draft save/load/clear to localStorage (crash recovery). Drafts are **slimmed and capped at 2MB** (see below)
- `undoHistory.ts` — Undo-history merge policy: new history on pause or sentence boundary, never on deletion
- `batchUndo.ts` — Single-slot undo record for batch ops; `undoBatch(id)` must validate the batch id
- `openTabs.ts` — Tab list logic (dedupe-to-end, cap eviction, which tab to activate after close)
- `commentAnchor.ts` — Selection→anchor, plus `resolveAnchor` re-location when the doc was edited
- `outlineActive.ts` — Scroll/offset → current heading (drives the outline highlight)
- `docExpanded.ts` — Doc-tree expanded-set persistence (stores *expanded* ids, capped at 500)
- `debounce.ts` — Debounce with `cancel()` / `flush()` (used by draft sync & search)
- `platform.ts` — `isMac` / `modKey` for platform-aware shortcut labels
- `markdownToHtml.ts` — Markdown → editor HTML, each block tagged with `data-md` (its source).
  `markdownToEditorHtml('')` **must** return `'<p><br></p>'`: an empty contenteditable has nowhere to
  put the caret, so a new document would be untypable. `refreshBlockDataMd` re-syncs `data-md` after each
  write-back — it is the basis of every offset lookup, and stale values silently break caret position,
  slash detection and comment anchors. Empty blocks get `''` (they carry no source), non-empty blocks map
  to parse results in order; **do not** skip the whole sync when counts differ (pressing Enter creates an
  empty block, which `parseMarkdownBlocks` drops, so counts always differ). Blocks with **no text but real
  source** — `hr`, `img`, `pre`, `table` — must be excluded from the "empty block" test: treating `<hr>` as
  empty clears its `data-md` and shifts every later block's source by one, so later write-backs compare
  against the wrong source and can rewrite user content.
- `editorHtmlToMarkdown.ts` — editor HTML → Markdown. Reads `data-md` first and returns it verbatim when
  the block was not edited; this is what makes the MD→HTML→MD round trip lossless. **Never `trim()` the
  assembled document** — only strip trailing blank lines. Leading whitespace is semantic (4 spaces = an
  indented code block in Markdown), and trimming it silently changes how the document renders. A fuzz test
  (`markdownRoundTripFuzz.test.ts`, 200 random block combinations) guards this and caught exactly that bug.
- `domOffset.ts` — Markdown source offset ↔ rendered DOM position. Everything offset-based goes through it
  (caret, find jumps, comment anchors, slash detection). Two traps: list blocks have `- item\n- item` in
  source but `itemitem` as visible text, so offsets must be resolved **per line** (`<li>` ↔ source line),
  and the line's block marker (`- ` / `1. `) counts toward the source offset. Missing either makes slash
  detection resolve to the wrong character and the menu never appears.
- `markdownFormat.ts` — applies a format to the **Markdown string** (the contenteditable counterpart of
  `editorTextOps.wrapSelection`, which only knows `textarea.selectionStart`). Without it every toolbar
  button silently no-ops under the rich kernel. Code-block toggle scans **paired fences** rather than the
  caret's own line, because the caret usually sits on a content line, not a fence line.
- `richEditorFlag.ts` — `notes-rich-editor` switch; **default on**. Storage semantics matter: only an
  explicit `'0'` means off (`isRichEditorEnabled` returns `localStorage.getItem(KEY) !== '0'`). Do **not**
  revert to "store '1' = on, delete = off" — with the default flipped to on, deleting the key means
  "restore default = on", so users could never turn it off. To fall back to textarea: set `'0'` and reload.
- **Anything reading `textarea.selectionStart/End` needs a rich-kernel branch.** Those properties do not
  exist on contenteditable, so the old code's `if (!ta) return` guard turns into a *silent no-op* — the
  button looks alive but does nothing. Seven features shipped broken this way and were only caught by
  driving the real UI: insert-link dialog, font-size-on-selection, outline click-to-jump, outline
  scroll-follow, the status bar's line/column readout (stuck at "行 1, 列 1"), the find gutter's viewport
  band, and split-mode preview scroll sync. Port them with `RichEditorHandle.getSelectionRange()` /
  `selectRange()` / `getCursorInfo()`, or pass a **getter** for the scroll container (see below).
- **Scroll consumers must accept a generic container, and pass it as a getter.** `FindMatchGutter` and
  `usePreviewScrollSync` only knew `textareaNode`/`textareaRef`; under the rich kernel both are null, so the
  viewport band froze and split-mode sync did nothing. They now take the editor root instead. Pass it as
  `() => node` rather than the node itself: these callbacks *write* `scrollTop`, and capturing a DOM node
  in a `useCallback` trips `react-hooks/immutability` ("cannot modify hook arguments").
- **Image/attachment insertion must be branched too, and the write-back guarded.** `insertImage` ended in
  `insertTextAtCursor(textareaRef.current, …)` and then wrote `textareaRef.current?.value || ''` — under the
  rich kernel the node is null, so the image vanished *and the whole document was overwritten with an empty
  string*. `useEditorFormatting` now takes `onRichInsert(markdown)` and only writes back when a textarea
  exists.
- **Never load images through `URL.createObjectURL`.** The app CSP is `img-src 'self' data: file:` — no
  `blob:` — so any `<img src={objectUrl}>` is blocked and the surrounding logic fails silently. `compressImage`
  did exactly that, which is why pasted images were never actually compressed. Use `createImageBitmap`
  (decodes straight from the File, no URL involved), with a data-URL `Image` fallback.
- **`useEditorKeys` only mounts on the textarea branch.** Line-editing shortcuts (`Ctrl+D` duplicate,
  `Alt+↑/↓` move, `Ctrl+Shift+K` delete) therefore did *nothing* under the rich kernel until they were
  re-implemented per block inside `RichEditor`. When adding a shortcut, check both branches.
- **Tab must be intercepted inside the editor.** A contenteditable leaves Tab as focus navigation, so
  pressing it while writing moved focus onto a toolbar button — the user then types into nothing. `RichEditor`
  now prevents default and indents instead (list items nest; plain paragraphs get two spaces).
- **Undo/redo under the rich kernel must call `RichEditorHandle.forceRender()`** after `undoRaw`/`redoRaw`.
  Undo and typing both go through `updateDocContent`, so the editor cannot tell them apart and will skip
  the rebuild it thinks is unnecessary — undo looks fine while **redo silently does nothing**. Verified by
  `scripts/rich-editor-check.mjs`, which drives the real toolbar buttons.
- `clipboard.ts`, `sanitize.ts` (`escapeRegExp` only) — misc helpers

### Electron Layer (`electron/`)
- `main.cjs` — Main process: window creation (CSP headers, `will-navigate` guard, `setWindowOpenHandler` deny), IPC handlers with payload validation, JSON store write queue, throttled backups (1/min, keep 10)
- `preload.cjs` — Context bridge exposing a whitelisted `notesApi`

### AI Layer (`electron/ai/` + `src/services/ai/`)
- **All AI network calls happen in the main process.** Production CSP is `connect-src 'self' ws:`, so the renderer cannot reach external APIs — do NOT relax CSP; keep the main-process proxy. Zero new runtime dependencies (Node 22 global `fetch` / `AbortController` / `node:crypto` only).
- Main process: `prompt-templates.cjs` (messages + style/length/action → temperature/max_tokens, single source of truth), `openai-adapter.cjs` (baseUrl normalization, request build, markdown normalization), `sse-parser.cjs`, `error-map.cjs`, `retry.cjs`, `lru-cache.cjs`, `concurrency.cjs`, `ai-validate.cjs` are **pure** (must not `require("electron")` so vitest can import them). `config-store.cjs` (safeStorage) and `ai-service.cjs` (orchestration, DI `fetchImpl`) are the only IO layers. IPC registration lives in `electron/ipc/handlers-ai.cjs`.
- **Cross-IPC contract: return envelopes, never throw.** `ipcMain.handle` errors are flattened to a message string (losing `code`/`retryable`), and preload's `withErrorHandling` rewraps them — AI channels deliberately bypass it and return `{ ok: false, error }`.
- **requestId is generated by the renderer** and the stream callback must be registered *before* `ai:stream:start`, otherwise the first chunk is lost. One `ipcRenderer.on` in preload + a requestId→callback Map (never `on`/`removeListener` per call — that triggers `MaxListenersExceededWarning`). Events are sent with `event.sender.send` (never broadcast; multi-window would leak content across windows).
- **Streaming text never enters `useNotesStore`.** `updateDoc` writes an auto version snapshot on every change (30s merge, max 50) and re-renders all subscribers — per-chunk writes would blow the version cap and pollute the undo stack. Stream into local state; write back once via `updateDocContent` after the user confirms.
- `sse-parser.cjs` needs a **per-request `TextDecoder` with `{ stream: true }`** — Chinese is 3 bytes/char and will straddle TCP chunks; a shared decoder also lets concurrent streams corrupt each other's state.
- Never retry after a chunk has been emitted (`canRetry: () => !emittedChunk`), or the user sees the text twice.
- `AiWriter` is mounted permanently and only toggled by `isOpen`, so `useAiWriter` must cancel in-flight streams when `isOpen` flips to false.
- AI config lives in `<userData>/ai-config.json` (API key encrypted via `safeStorage`) — **never** in the Zustand store / localStorage / `notes-data.json`, all of which get copied into backups and exports.
- `TEMPLATE_VERSION` in `prompt-templates.cjs` participates in the cache key: bump it whenever templates or the style/length/action mappings change. Renderer option keys must stay in sync with `prompt-templates.cjs` (cross-asserted by `tests/unit/aiPromptTemplates.test.ts`).
- See `docs/AI-集成文档.md` for the full interface spec, provider table, error codes and performance targets.

### Data Flow
1. User edits → `EditorContent` → `updateDocContent` → `coreSlice.updateDoc` (immer) → auto version snapshot + `updatedAt` bump
2. `useDraftSync` (800ms debounce) writes a **slimmed** snapshot to localStorage (version snapshots/comments stripped, capped at 2MB with progressive degradation); `useAutoSave` (3s debounce) → `saveNotes()` → `window.notesApi.save()` → Electron writes `notes-data.json`
3. On load: `useAppInit` → `loadNotes()` → normalize missing fields → set state; draft recovery compares localStorage draft vs loaded data

### Key Patterns
- **No routing** — all views managed by `activeLeftMenu` / `activeView` state (UI state lives in `src/hooks/useUIState.ts`)
- **Document hierarchy** — `parentId` field enables tree structure; `DocTree` renders nested items
- **Undo/redo** — `undoRedoSlice` snapshot stacks (max 200) via `src/hooks/useUndoRedo.ts`; global Ctrl+Z/Y wired in `App.tsx`, editor Ctrl+B/I handled in `EditorContent`. Merge policy lives in `src/utils/undoHistory.ts`: a new history entry starts on a pause (>1s) **or** when the inserted text ends with a sentence boundary (space/punctuation/newline); deletions never start one
- **Version history** — auto `type: 'auto'` snapshots on content/title/tags change (30s merge, max 50); `versionSlice.createVersionSnapshot` adds user-triggered `type: 'manual'` snapshots, which are kept preferentially when the 50-entry cap evicts
- **Vite config** — `base: './'`; chunks via Rolldown's `build.rollupOptions.output.codeSplitting.groups`
  (react-vendor / zustand / immer / jszip / katex / markdown). **`manualChunks` is a no-op on Vite 8 / Rolldown** —
  it is accepted silently and ignored, so any chunking change must be verified against the emitted
  `dist/index.html` modulepreload list, not just the config. `react/jsx-runtime` must stay in `react-vendor`:
  it is imported by every `.tsx` file, so if it lands in the markdown chunk the entry statically depends on
  that chunk and pulls ~630KB of markdown + KaTeX into the startup preload.
- **Preview is lazy** — `MarkdownPreview` (react-markdown + unified + KaTeX) and `PresentationMode` are
  `React.lazy`-loaded from `Editor.tsx` / `TemplateCenter.tsx`. Keep them that way; a static import puts
  ~630KB back into the startup preload even though the default view is edit-only.
- **Never put mermaid in a `codeSplitting` group.** It was tried: chunk count dropped 117 → 40, but grouping
  promoted mermaid to a static dependency, so the 3MB chunk landed in `index.html`'s modulepreload and the App
  chunk imported it statically — startup preload went 190KB → 3.2MB. The many small async chunks are the
  cheaper trade; verify any chunking change against `dist/index.html`, not the config.
- **Startup render cost** — `App.tsx` must not subscribe to per-keystroke state (`activeDoc`,
  `lastMutationAt`, `notebooks`). Editors subscribe to `activeDoc` themselves; `useAutoSave` uses
  `store.subscribe` for its side effect. Subscribing at the shell re-renders the whole tree on every keypress.
- **Tabs** — `tabSlice` stores only `{notebookId, docId}` references (never doc content) and is persisted to
  localStorage, not `notes-data.json`. Registration is automatic: `coreSlice.setActiveDocId` calls `openTab`,
  so every existing "open a document" entry point gains tabs without being touched. `pruneOpenTabs` drops
  references to deleted docs (otherwise a tab click opens a ghost document).
- **Comments** — `Comment.anchor` (`{start, end, quote}`) is optional; without it a comment is document-level.
  Always resolve through `utils/commentAnchor.resolveAnchor` before highlighting/jumping: anchors drift when
  the doc is edited, and a quote that no longer exists must degrade to a plain comment rather than point at
  unrelated text. `anchorFromSelection` caps `quote` at 500 chars (the range still spans the full selection).
- **Quick notes must travel with backups** — quick notes live in their own localStorage key for fast editing,
  but they are **not** free to omit from persistence: `saveNotes`'s payload includes them, `withQuickNotesForExport`
  adds them to export payloads, and `importQuickNotes` merges them by id keeping the newer `updatedAt`.
  Omitting them silently loses every quick note when the user restores a backup on another machine.
- **Search** — `searchSlice` caches lowercased text per doc (`WeakMap` keyed by object, invalidated by
  `updatedAt`). Empty queries must return `[]`; a bare empty term would make `every()`'s `includes('')`
  match the entire library. Tokenize/tag-name/date-boundary work is hoisted out of the per-doc loop.

## Conventions
- UI text is in Chinese (zh-CN)
- All dates use `toISOString()`; display via `toLocaleString('zh-CN')`
- No CSS framework — plain CSS in `src/App.css`, `src/index.css`, `src/styles/*.css`
- Keep IPC payloads validated in `main.cjs` (see `assertStorePayload` / `assertExportPayload`) — never trust the renderer
