# 富文本编辑器内核

> 状态：**默认开启**。功能完整、三层验收通过。
> 需要退回旧内核时见下文「如何关闭」。

## 这是什么

编辑器内核从「纯 textarea + Markdown 源码」改为「contenteditable 单块 + Markdown 即时转换」。
目标是把操作手感与视觉布局对齐语雀 —— 输入 `# ` 立刻变成标题、选中文字浮出格式工具条、
标题在正文里而不是顶部栏。

**Markdown 仍是唯一真实源**：每次编辑都转回 Markdown 存盘，存储格式、导出、
版本快照、备份全部不变。换成富文本内核不会产生新的文件格式。

## 如何关闭（退回 textarea 内核）

```js
localStorage.setItem('notes-rich-editor', '0')   // 关闭
localStorage.removeItem('notes-rich-editor')     // 恢复默认（开启）
```

改完**需要刷新页面**。开关是会话级读取的（`useState` 惰性初始化），不做热切换。

> 注意存储语义：**关闭必须显式写入 `'0'`**。删除键等于"恢复默认"，而默认是开启 ——
> 所以 `removeItem` 不会关闭，只会回到开启。这是刻意的设计：默认值从关闭翻转为
> 开启后，若仍用删除表示关闭，用户就永远关不掉了。

两种内核读写同一份 Markdown，来回切换**不需要迁移数据**。

## 已知限制

这些是**有意的取舍**，不是缺陷：

1. **不做块级拖拽排序**。语雀可以拖动手柄移动整个块，这需要完整的块模型
   （每个块独立标识、独立状态）。当前方案是单块 contenteditable，加拖拽会
   显著增加复杂度与出错面。若需要该能力，应改用 TipTap / Lexical 这类块编辑器 ——
   但那会引入运行时依赖，与项目「dependencies 只允许 jszip」的硬约束冲突。

2. **行内格式在离开块时渲染**。输入 `**加粗**` 时，加粗效果在按 Enter 或失焦后
   出现，而不是在敲完第二个 `*` 的瞬间。原因：输入过程中替换 DOM 会与浏览器的
   光标定位持续冲突（实测会把后续字符并进 `<strong>`）。**在标记对后面继续打字**
   时则会即时渲染。

3. **表格 / 代码块不在富文本层编辑**。它们在编辑器里正常显示，但内容编辑仍走
   Markdown 源码（与旧内核一致）。这两类块结构复杂，富文本化收益低于出错风险。

4. **顶部工具栏仍是两行**。语雀是单行精简工具条。改它需要动所有格式按钮的布局，
   且旧内核共用同一套组件，风险高于收益，故保留现状。

## 实现要点（改动前必读）

### 数据完整性

- **往返必须无损**。`editorHtmlToMarkdown` 优先读块的 `data-md`（原始 Markdown），
  未编辑的块直接返回原文。这是整个方案成立的前提 —— 有损会让用户每敲一个键
  都静默改写自己的文档。
- **不要 trim 组装后的文档**。只去尾部空行。行首空格有语义（Markdown 里
  4 个空格 = 缩进代码块）。
- **`data-md` 必须保持同步**。它是所有偏移换算的依据，过期值会静默破坏光标位置、
  斜杠检测、评论锚点。`refreshBlockDataMd` 在每次回写后同步。
- **无文本但有源码的块**（`hr` / `img` / `pre` / `table`）不能当空块处理：
  清空其 `data-md` 会让后续块的源码整体前移一位。

### 偏移换算

`domOffset.ts` 是唯一入口。两个坑：

- 列表块源码是 `- 甲\n- 乙`，可见文本是 `甲乙` —— 偏移必须**按行**解析
  （`<li>` ↔ 源码行）。
- 行的块标记（`- ` / `1. `）**计入**源码偏移。漏掉会让斜杠检测定位到错误字符。

### 内核分流

**凡读 `textarea.selectionStart/End` 的地方都必须按内核分流。**
contenteditable 没有这些属性，旧代码的 `if (!ta) return` 会变成**静默失效** ——
按钮看着活着，实际什么都不做。已经踩过 7 次：

插入链接弹窗、字号作用于选区、大纲点击跳转、大纲滚动跟随、
状态栏行列号、查找刻度带视口、分屏滚动同步。

改用 `RichEditorHandle` 的 `getSelectionRange()` / `selectRange()` / `getCursorInfo()`；
滚动容器用 **getter** 传（`() => node`），因为那些回调会写 `scrollTop`，
把 DOM 节点捕获进 `useCallback` 会触发 `react-hooks/immutability`。

### 撤销/重做

撤销/重做后必须调 `forceRender()`。撤销与用户打字都走 `updateDocContent`，
编辑器无法区分，会误判「内容没变」而跳过重绘 —— 表现为**撤销正常但重做无反应**。
