## 1. 结论先行

**一句话诊断：功能广度已经到了「能用」，但「消费级」的四道门槛还没跨过去。**

| # | 门槛 | 现状（有证据） | 用户体感 |
|---|---|---|---|
| 1 | 装不上、装不像 | package.json 无 electron-builder / forge 配置、无 autoUpdater；public/ 只有 favicon.svg 与 icons.svg（无 .ico / .icns）；关于框硬编码「学习笔记 - 开发版」 | 这是个源码项目，不是个产品 |
| 2 | 进不去、不知道干嘛 | 无首启引导；默认数据只给一篇静态「欢迎使用」；空状态多为「暂无 XX」纯文案 | 打开之后我该做什么 |
| 3 | 不敢信 | 数据加载失败时零提示且自动保存永久停摆；错误日志只写不读；备份恢复藏在侧栏「更多」二级菜单 | 出问题我只能自己猜，甚至不知道已经出问题了 |
| 4 | 不顺手 | 高频操作要 2~3 次点击；行内操作按钮 hover 才出现（键盘/触屏不可达）；无文档内查找；无系统暗色跟随 | 能用，但不像语雀那么顺 |

### 1.1 必须先修的三个「隐性事故级」缺陷

这三条不是优化建议，是**已经在产生错误结果的 bug**，且每一类都属于消费级产品不可接受的那一档。它们优先级高于本方案中任何一条体验项。

| 编号 | 缺陷 | 证据 | 后果 |
|---|---|---|---|
| **BUG-1** | **数据加载失败时零提示，且自动保存永久停摆**：coreSlice.loadNotes 内部 catch 后只执行 `set({ loadFailed: true })`，不 rethrow；useAppInit 的 `.catch` 分支因此永远不可达，那句「加载笔记失败，请检查数据文件」从未出现在用户眼前；loadFailed 全库无任何重置路径 | coreSlice.ts:205-209（catch）、214-217（阻写）；useAppInit.ts:50-70（不可达 catch） | 用户看到空应用，以为数据全丢；此后**所有新写内容都不再落盘**（重启后若文件仍异常则再次丢失）→ 事实上的数据丢失循环 |
| **BUG-2** | **主题 / 字体 / 自定义主色重启后失效**：全库唯一设置 `data-theme` / `data-font` 的地方是 useTheme / useFont，而这两个 hook 只在 EditorHeader 与 SettingsPanel 内被调用；App.tsx 与 main.tsx 都没有主题初始化 | shared/hooks/index.ts:26-54（useTheme）、168-187（useFont）；调用点仅 EditorHeader.tsx:105、SettingsPanel.tsx:32-33 | 选过暗色 / 霞鹜文楷的用户重启后看到亮色 + 默认字体，直到首次打开文档或打开设置；启动首帧必然亮色 → 深色用户每次启动被闪一下（FOUC） |
| **BUG-3** | **编辑器没有任何查找能力**：全库 findInPage 零命中，keyboardSlice 的 35 条快捷键里没有 Ctrl+F / Ctrl+H | 实测 grep findInPage / webContents.find = 0；keyboardSlice.ts DEFAULT_SHORTCUTS 无查找项 | 长文档里找一句话只能靠肉眼；与 S1（搜索跳转不带定位）叠加后形成完整断链：**搜得到，但打开后找不到那句话** |

## 2. 消费级基准：8 条验收线

先把「消费级」这个词变成可验收的标准，后面所有条目都挂在这 8 条上。

| 维度 | 消费级标准 | 语雀做法 | 本项目现状 |
|---|---|---|---|
| 1 可获取 | 下载 → 安装 → 启动 ≤ 3 步，无命令行 | 官网下载安装包，Win/Mac 双端，自动更新 | 需 clone + pnpm install + 手动 build，无安装包 |
| 2 可理解 | 新用户 60 秒内知道第一步做什么 | 首启引导 + 大量示例模板 + 空态引导按钮 | 只有一篇静态欢迎文档 |
| 3 一致 | 同类操作全局只有一种交互、一种视觉 | 统一的卡片/列表/菜单体系 | 内联确认弹窗 4 处重复、emoji 与 SVG 图标混用 |
| 4 高效 | 高频动作 ≤ 1 击或 1 个快捷键 | 快速跳转、斜杠命令、块手柄、快捷键体系 | 斜杠命令与快捷键已强；缺全局快速跳转与文档内查找 |
| 5 可靠 | 崩溃可自愈、数据可找回、动作必有反馈 | 服务端多副本 + 历史版本 | 自动备份/版本/草稿体系强，但**失败路径无出口**（BUG-1） |
| 6 可预期 | 每个界面都有加载 / 空 / 错误 / 成功四态 | 全站四态齐备 | 骨架屏只在 3 处；多处内联「加载中...」；空态多为纯文案 |
| 7 包容 | 键盘可完成主流程、触屏可用、跟随系统主题、支持缩放 | 键盘快捷键完整、移动端 App | 59 处 aria / 24 文件；无 @media (hover) 兜底；无系统暗色；无键盘树导航 |
| 8 可交付 | 安装包、签名、自动更新、崩溃上报、可回滚 | 完整的发布与灰度通道 | 全部缺失（D1-D7） |

## 5. 三条体验主线与北极星指标

体验优化最容易失控的地方是「什么都想做」。用三条主线收口：**首次 5 分钟、日常 30 秒、长期不怕丢**。

| 主线 | 用户旅程 | 北极星指标 | 现状 | 目标 |
|---|---|---|---|---|
| 首次 5 分钟 | 安装 → 启动 → 写下第一篇 → 保存成功 | Time to First Note | 需命令行构建，无引导，不可度量 | ≤ 3 分钟，且全程无命令行 |
| 日常 30 秒 | 打开应用 → 找到昨天那篇 → 光标落在上次位置 | Time to Resume（p95） | 依赖手动点树；无快速打开；无查找 | ≤ 15 秒 |
| 长期不怕丢 | 崩溃 / 断电 / 文件损坏 → 内容完整找回 | 数据找回成功率 | 有备份与草稿，但失败路径无出口（BUG-1） | 任何异常场景下最近一次成功保存内容 100% 可恢复 |

补充守卫指标（每轮回归都看）：

- 未捕获异常数 / 白屏次数：目标 0（连续 8 小时使用）
- 启动到可交互 p95：目标 < 1.5s
- 首次搜索出结果 p95：目标 < 300ms
- 高频动作点击数：打开任意文档 ≤ 1 击（Ctrl+P 或树内单击）
- 键盘可完成率：主流程（找库 → 开文档 → 写 → 保存 → 查找）100% 无需鼠标

## 9. 明确不做 / 后置（附理由）

消费级产品最容易死在「什么都想要」。以下方向建议**明确不做**或**后置到有明确需求时**：

| 方向 | 结论 | 理由 |
|---|---|---|
| 实时多人协作编辑 | 不做 | 需要服务端账号体系、权限模型、OT/CRDT 内核与在线存储，与「本地优先、零后端」的定位冲突；用「导出分享包 + 本地分享预览」替代 |
| Tiptap / ProseMirror 所见即所得重构 | 后置 | 需重建文档模型（字符串 → 块树），牵连版本历史、分享、演示、搜索、导入导出全链路，回归面极大（见 editor-gap-analysis 的 C 层结论）|
| 云端同步 | 后置 | 可先用 WebDAV / 自建目录同步作为中间态，避免账号与合规成本 |
| 知识图谱 | 不做 | 语雀本身没有；对本产品用户价值低于双链与反向链接 |
| 画板 / 思维导图 | 不做 | 需要独立编辑器内核，成本与收益严重不匹配 |
| 移动原生 App | 后置 | 现有响应式 Web 版可覆盖预览与轻编辑；原生 App 属独立项目 |
| 插件体系 | 不做 | 在核心体验达到消费级之前，插件只会放大不可控面 |

排查时靠的是对照实验（换路径复现 / 不换路径复现），而不是读代码。

**顺带修掉的历史遗留**：`optimizeDeps.noDiscovery` 曾被我当作"缩小扫描范围"的优化启用，
实测它会让 `react-dom/client` 这类**子路径入口**不被预构建，报
`does not provide an export named 'createRoot'`，应用启动即崩。已移除并写明原因。
