# 工具-CRLF多行edit匹配失败

## 触发条件
在本仓库（Windows，CRLF 行尾）用 `edit` 工具做**多行** old_string 替换：匹配不到、报错不提示行尾原因。反复重试多行匹配纯属浪费。

## 首选姿势
- 小文件（< ~300 行）：`read` 全文后 `write` 全量重写。
- 大文件：用**唯一单行锚点**做替换/前插（单行不含 `\n`，不受行尾影响）。需要替换多行块时，锚定块首行 + 块尾行分两次单行操作，或 read 精确区间后 write。
- 判据：edit 报「old_string 找不到」但 read 明明能看到这段文字 ⇒ 先怀疑 CRLF，别怀疑自己抄错。

## 反面清单
- 多行 old_string 反复微调重试（换空格/换缩进）——不是空白问题，是 `\r\n` vs `\n`。
- 用 pwsh `Get-Content` 按行号切片写回大文件——极易连带删掉区间内其它声明（2026-10-25 已踩过，RichEditor 误删类型/常量）。

## 验证方式
edit 成功后立即 `npx tsc -b --noEmit`（或定向 eslint 该文件），确认没有连带破坏。
