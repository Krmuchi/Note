# 工具-实机脚本失败进程吊死

## 触发条件
Playwright 实机验收脚本（rich-editor-check / complex-doc）任一断言或 locator **抛错中断**：
错误已打印、失败已明确，但 node 进程永不退出、后台任务永远 `running`（实测挂 19 分钟无输出）。

## 首选姿势
- **根因在 `scripts/_preview-server.mjs` 的 catch 只记 exitCode 不退进程**：断言抛错时脚本末尾的
  `browser.close()` 不会执行，node 被 Playwright 的连接吊住。已修：finally 里 stop preview →
  排空 100ms → `process.exit(exitCode)`（改动后任何路径都必退）。
- **定位卡点用「日志落盘 + 后台跑」**：`node script.mjs *> check.log` 后轮询文件 —— 管道直读拿不到
  中间输出（pwsh 后台任务只在结束时吐 stdout），挂住时 `Get-CimInstance Win32_Process` 看
  node/chrome-headless-shell 命令行判断卡在哪层。
- **失败要软**：关键 locator 加 `click({timeout:8000}).catch(…)` + `[diag]` 打印（命中计数等），
  让失败以 check(false) 进总报告而不是抛错走吊死路径；一次跑完拿到全量结论比卡死在半路有用。
- 诊断「按钮恒 disabled / 元素恒 null」时先写**最小探针**（逐步 console.log + try/finally 关浏览器），
  把「测试环境没造出前提」与「产品回归」一次分开（本轮探针证明 count=1/1 正常，问题在主脚本前提）。

## 反面清单
- 失败后不看 process 列表直接重跑：旧 preview/headless 常占着 5215 端口与 `--strictPort` 撞车，
  新任务表现为「preview 永不就绪」——先 taskkill 按 **CommandLine 匹配**清场再跑。
- 清场命令的 CommandLine 匹配串写在命令本身里 → 杀到自己的 pwsh（job runner exit 1）。
  必须 `Get-CimInstance … | Where { $_.ProcessId -ne $PID … }` 排除自身。

## 验证方式
修后用「故意失败的断言」跑一遍：错误进报告、进程 3~5 分钟内自行退出、`EXIT=` 行出现。
