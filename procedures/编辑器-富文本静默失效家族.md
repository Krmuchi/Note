# 编辑器-富文本静默失效家族

## 触发条件
给富文本内核（RichEditor）加/改功能后「按钮看着能点但没效果」「光标/格式落到别处」「拼音被打断」「重做无效」。这是本项目复发最多的缺陷家族（CLAUDE.md 记载过 7+1 个同类）。

## 首选姿势
- **偏移换算**：一律按行映射（li↔源码行、blockquote p↔行），行首标记（`- `/`1. `/`> `/`- [x] `）计入、换行计 1、嵌套容器取**最深**匹配。公共函数在 domOffset.ts（blockLineMap/linePrefixLen），别再做整块近似。验证：`- aa\n- bb` 选第二项应得 [7,9]。
- **撤销/重做**：store 的 undoRedoSeq 序号驱动重建，覆盖所有入口；别靠 lastWrittenRef 内容比对（重做回到刚写出的值会被误判无需重建）。
- **IME**：keydown 守卫 `isComposing || keyCode===229`，**且** composition 期间 input 也守卫（否则写脏拼音快照），compositionend 补跑一次。
- **批量格式**：同一份演进源码上串行折叠、一次回写；别 forEach 连调 applyFormat（各读渲染闭包旧值互相覆盖）。
- **新快捷键/新按钮**：先查两个内核是否都走注册表；硬编码分支（find/replace/行编辑类）要在 keyboardSlice 标 `fixed: true`，设置页不给录制入口——否则制造「能改但无效」的死设置。
- 读 textarea.selectionStart 的代码必须有富文本分支（getSelectionRange/selectRange 端口）。

## 反面清单
- 整块 sourceOffsetForVisible 近似（列表/引用第二行起必错）。
- 只包装某一个撤销调用点加 forceRender（键盘路径绕过）。
- 只守 keydown 不守 input 的 IME 守卫。
- 给硬编码键位开放自定义。

## 验证方式
`npx vitest run src/utils/__tests__/domOffset.test.ts src/store/__tests__/undoRedoSlice.test.ts src/hooks/__tests__/useSmartInput.test.ts` + `npm run verify:editor`（真机 32+11 断言，含 Ctrl+Y/列表加粗/IME）。
