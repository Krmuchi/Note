# 流程-子代理过夜静默中断

## 触发条件
派发长时子代理（审计/大重构）后宿主休眠或重启：所有子代理「failed before it finished / no closing message」，无报告无现场。

## 首选姿势
1. 先 `list_agents` 确认状态，再 `send_message` 逐个唤醒原代理：「基于已有进展直接整理输出最终报告，不要重新排查」——上下文还在，通常几分钟就能收尾。
2. 唤醒后 lead 继续做**无文件冲突**的自有工作，等完成通知。
3. 派发长任务时就要求「边查边分段汇报」或拆小范围，降低全损风险。
4. 修复波按**文件所有权**分区派发（独占清单 + 严禁触碰清单），跨代理接口（字段名/通道名）由 lead 先约定再分发，避免集成时两边对不上。

## 反面清单
- 直接重开新代理从头重查（浪费已完成的 80% 工作）。
- lead 在代理运行期间编辑其所有权文件（并发覆盖，无冲突检测）。
- 全量 build/verify 与代理的在途编辑并行（产物混入半成品）。

## 验证方式
代理收尾报告须含：改动文件清单、逐项测试证据、未决事项；lead 按所有权核对 git status 与报告一致，再跑统一门禁。
