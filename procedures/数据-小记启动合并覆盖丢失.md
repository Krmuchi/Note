# 数据-小记启动合并覆盖丢失

## 触发条件
改动小记（quickNoteSlice / coreSlice.loadNotes）的持久化逻辑，或用户报"小记丢了/删了又回来"。小记双存储：localStorage（主）+ notes-data.json（备份副本），启动/恢复时按 id 合并。

## 首选姿势（三条根因修复，勿回退）
1. **启动合并顺序**：先 `loadQuickNotes()` 读本机 localStorage，再 `importQuickNotes(loaded.quickNotes)` 并磁盘。合并保留较新 updatedAt。
2. **立即落盘**：小记变更是离散动作（新增/保存/删除），同步写 localStorage，不用防抖（800ms 窗口内切视图/崩溃会丢最后一次编辑）。
3. **删除墓碑**：删除写 `notes-quick-notes-deleted`（id→时间，90 天 TTL），loadQuickNotes/importQuickNotes 跳过墓碑 id——否则磁盘旧副本把已删小记"复活"。
4. 小记变更 bump `lastMutationAt`，随全量保存进备份副本。

## 反面清单
- 先并磁盘再读本机（旧 bug：磁盘旧副本冲掉本机较新编辑**并落盘**，永久丢失）。
- `loadQuickNotes` 直接 `state.quickNotes = notes` 覆盖内存（面板重挂载丢编辑）。
- 恢复防抖持久化（窗口期数据丢失路径复活）。

## 验证方式
`npx vitest run src/store/__tests__/quickNotePersistence.test.ts`（11 用例锁死三条根因 + 墓碑 + 合并语义）。
